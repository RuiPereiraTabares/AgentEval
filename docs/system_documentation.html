Article Evaluation System

A multi-agent LLM pipeline that evaluates whether Microsoft support articles adequately address customer support cases. Eight specialized agents collaborate through an orchestrated pipeline to score articles, identify documentation gaps, and classify transfer reasons.

8 Specialized Agents Kepner-Tregoe Framework Weighted Scoring Multi-Provider LLM

Architecture Overview

The system is orchestrated by a central Orchestrator class that coordinates all agents in a defined sequence. The pipeline adapts its execution path based on whether an article URL is provided and on intermediate scoring results.

Agent Directory

Each agent inherits from BaseAgent and follows a consistent pattern: call the LLM with a specialized prompt, parse the JSON response, and fall back to heuristics if the LLM call fails.

🔍

IssueParserAgent

agents/issue_parser.py

Parses raw customer issue text into a structured Issue object, extracting product, version, error codes, symptoms, keywords, environment, and severity.

Input

Raw issue text string + optional SAP product metadata

Output

Issue dataclass with fields: product, version, error_codes, symptoms, issue_type, keywords, environment, severity

Issue Types

configuration error how-to troubleshooting performance

Fallback

Heuristic product detection from keyword map; regex extraction of error codes (hex/numeric patterns).

★

DescriptionQualityAgent

agents/description_quality_agent.py

Evaluates issue description quality using the Kepner-Tregoe Problem Statement framework across four dimensions.

KT Dimensions
Identity (WHAT)35% weight
Location (WHERE)25% weight
Timing (WHEN)20% weight
Magnitude (EXTENT)20% weight
Output

DescriptionQualityResult with per-dimension scores (0-100), analyses, overall score, verdict, missing elements, and improvement suggestions.

Verdicts

≥80 well_defined ≥60 mostly_defined ≥40 partially_defined <40 poorly_defined

If description_quality_score < 40, the system sets evaluation_reliability_warning = True since a poor description reduces evaluation confidence.
🎯

RelevanceAgent

agents/relevance_agent.py

Scores how well a fetched article matches the customer issue. Carries the highest weight in the overall score at 40%.

Input

Issue + Article (content truncated to 8,000 chars)

Output

RelevanceResult with score, matched/unmatched aspects, product_match, version_match, is_outdated flag, verdict.

Score Guide

90-100 Excellent 70-89 Good 50-69 Partial 30-49 Poor 0-29 Irrelevant

✅

CompletenessAgent

agents/completeness_agent.py

Assesses whether an article provides complete information to solve the issue. Weighted at 30%.

5 Evaluation Aspects
  • has_prerequisites — setup/requirements listed
  • has_step_by_step — ordered resolution steps
  • has_examples — code samples / screenshots
  • has_troubleshooting — alternative paths / common issues
  • has_success_criteria — how to verify resolution
Verdicts

≥90 complete ≥70 mostly_complete ≥50 incomplete <50 severely_lacking

🔬

ValidityAgent

agents/validity_agent.py

Determines whether the article's solution would actually work for the customer. Weighted at 30%.

Evaluation Criteria
  • addresses_root_cause — targets the actual problem
  • is_current_solution — not outdated
  • environment_compatible — works in customer's environment
Output

ValidityResult with score, booleans above, potential_issues list, confidence_level (high/medium/low), verdict.

Verdicts

≥80 valid ≥60 likely_valid ≥40 uncertain ≥20 likely_invalid <20 invalid

🔎

SearchAgent

agents/search_agent.py

Generates optimized search queries to find better or supplementary Microsoft documentation. Triggered when overall score < 70 (or always when no article is provided).

Output

SearchResult with up to 5 RecommendedArticle objects (Microsoft Support URLs), search terms, and a better_alternative_found flag.

Search Domains

support.microsoft.com, learn.microsoft.com

Fallback

Builds queries from issue data: product + error codes, product + symptoms, product + issue type, keywords.

📋

GapAnalysisAgent

agents/gap_agent.py

Identifies documentation gaps and recommends content creation actions. Triggered when overall score < 60 (or always when no article is provided).

Output

GapAnalysisResult with documentation_gaps, suggested_content_outline, required_expertise, priority, estimated_effort, recommendation.

Recommendations

create_new augment_existing combine_multiple

Priority / Effort

Priority: high | medium | low
Effort: small | medium | large

🔁

TransferReasonAgent

agents/transfer_reason_agent.py

Classifies the root cause of why a support case was transferred. Always runs last after all other agents, using their outputs as inputs to the classification decision tree.

Input

Issue, DescriptionQualityResult, overall_score, relevance_score, contains_citations flag, verdict.

Transfer Reason Values

not_transferred customer_escalation poor_description poor_description_bad_citation no_citation_found bad_citation_match inadequate_article unknown

Escalation Detection

Scans for 13+ regex patterns indicating customer frustration or explicit escalation requests (e.g., "speak to a manager", "SLA breach", "business is stopped"). LLM escalation scan is triggered when text ≥ 30 chars and heuristic signals found or text > 200 chars.

Pipeline Flow

The Orchestrator coordinates agent execution in the following sequence. Each step feeds outputs to downstream agents.

1

Parse Issue

IssueParserAgent.evaluate(customer_issue, product_info) → structured Issue object. Transfer metadata (transferred, sr_status, reopened) is injected from CSV.

2

Evaluate Description Quality

DescriptionQualityAgent.evaluate(issue) → KT framework analysis. If score < 40, sets evaluation_reliability_warning = True.

?

Branch: Has Article URL?

The pipeline branches based on whether the input case contains article URLs (citations).

Path A — No Citation
SearchAgent generates recommended search queries
GapAnalysisAgent identifies documentation gaps (no prior evaluation data)
TransferReasonAgent classifies with contains_citations=False
Result: verdict="no_citation_provided", score=0, action="find_better_article"
Path B — Has Citation(s)
ArticleFetcher fetches each URL (HTTP GET, BeautifulSoup parsing, 30s timeout)
For each valid article, run the scoring triad in sequence:
① RelevanceAgent → RelevanceResult
② CompletenessAgent → CompletenessResult
③ ValidityAgent → ValidityResult
The best overall score across all URLs is selected.
3

Search (Conditional)

If best_score < 70: SearchAgent.evaluate(issue, best_score) generates search recommendations.

4

Gap Analysis (Conditional)

If best_score < 60: GapAnalysisAgent.evaluate(issue, relevance_result, completeness_result, validity_result) identifies documentation gaps.

5

Verdict & Action

ScoringUtils computes the overall verdict and action required based on score, relevance verdict, and search results.

6

Transfer Reason Classification (Always Last)

TransferReasonAgent.evaluate(...) runs with all evaluation data. Uses a cascading decision tree to classify the transfer reason.

✓

Output EvaluationResult

The final EvaluationResult is written to CSV and/or JSON with all scores, verdicts, recommendations, and transfer analysis.

Conditional Agent Triggers

SearchAgent triggers when overall_score < 70 — generates search queries to find supplementary or better articles.
GapAnalysisAgent triggers when overall_score < 60 — identifies documentation content that needs to be created or augmented.

Transfer Classification

The TransferReasonAgent uses threshold-based logic defined in TRANSFER_CLASSIFICATION_THRESHOLDS:

ThresholdValueMeaning
poor_description_ceiling40Description quality below this = poor description root cause
bad_citation_relevance_ceiling50Relevance below this = bad citation match
inadequate_article_overall_ceiling60Overall score below this = inadequate article

Escalation Detection Patterns

The agent scans issue text for 13+ regex patterns indicating customer frustration:

escalat(e|ed|ion) transfer me/this speak to a manager need a specialist unacceptable Nth time calling already contacted support previous case SLA breach business is stopped critical deadline executive sponsor VP is asking

If ≥ 2 escalation signals are detected, the transfer reason is immediately classified as customer_escalation.
